# Phase 4B — GPU axis GAP ANALYSIS (ELIPS vs FAISS CUDA + Metal)

Analysis only. Evidence cited `file:line`. ELIPS paths relative to repo root; FAISS
paths relative to `/tmp/faiss` as captured in `_faiss_3D.md` / `_faiss_3I_metal.md`.

ELIPS baseline (confirmed this pass): Metal is the only backend that compiles+runs; its
`compute_distances_batch` is a naive one-thread-per-(query,base) inline kernel dispatched in
a **single threadgroup** (`MetalBackend.mm:236-238`), `top_k` is CPU `std::partial_sort`
(`MetalBackend.mm:251-263`), `synchronize`/`is_idle` are no-ops (`MetalBackend.mm:267-268`),
and the real 111-LOC `.metal` is dead (not in `metal/CMakeLists.txt:7-9`). CUDA/HIP are
`#error` stubs; SYCL/Vulkan already removed in Phase 2.

## Biggest gaps (ranked)

1. **GPU top-k is missing (CPU `std::partial_sort`).** `MetalBackend.mm:251-263`. The single
   highest-value deliverable: FAISS ships `topk_threadgroup_*` with a smaller-index tiebreak
   that makes GPU results CPU-exact (`MetalDistance.metal:141-347`). Blocker, Phase 7.
2. **The distance kernel is a naive triple-loop in a single 1×1×1 threadgroup.**
   `MetalBackend.mm:67-117,236-238` — a correctness ceiling (nq·nb capped by
   `maxTotalThreadsPerThreadgroup`) and no tiling. FAISS has a tiled GEMM. Blocker, Phase 7.
3. **No real-kernel test coverage.** Every unit test runs `RecordingBackend` on CPU; real
   Metal only runs opt-in-by-hardware and skips silently. Nothing proves a kernel is correct.
   Blocker, Phase 7.
4. **The `.metal` is dead code — no metallib build chain.** `metal/CMakeLists.txt:7-9` never
   builds the shader; the backend uses an inline string. Must adopt `xcrun→metallib` +
   runtime discovery to make real kernels loadable. Major, Phase 7.
5. **Silent, un-logged fallback; `RequireGpu` is a no-op distinction.** Both branches
   `return std::nullopt` (`GpuDeviceManager.cpp:111-116`). FAISS throws explicitly. Major,
   Phase 7.
6. **No standalone `bf_knn`/`GpuDistanceParams` primitive, and no host-or-device
   transparency.** The clean reusable layer FAISS exposes is only reachable through index
   classes in ELIPS. Major, Phase 7.
7. **No query tiling / dataset-larger-than-device / typed-OOM-recoverable path.** Full
   `nq×nb` matrix allocated at once (`GpuSearchPipeline.cpp:14`); OOM swallowed silently
   (`GpuBruteForceIndex.cpp:50-53`). Major, Phases 7–8.
8. **No max-k cap, no metric/dtype validation.** No eager typed throws; errors degrade to
   empty results. Major, Phase 7.
9. **fp16 config flags are dead** (no fp16 kernel), and **IVFFlat/IVFPQ have no GPU scan
   kernels** (delegate to the same full-matrix path / CPU). Major, Phase 8.
10. **Selector ranks stub backends (cuda>hip) above the only real one (Metal).**
    `GpuSelector.cpp:8-14`. Minor but a live foot-gun once a CUDA stub is enabled. Phase 7.

## Where ELIPS is ahead of FAISS

- `DynamicBatcher` query coalescing has no FAISS counterpart (`DynamicBatcher.hpp:17-71`) —
  keep it, but it is currently untested (injected `search_fn`, no kernel exercised).
- Unified-memory zero-copy upload/download is already correct for the Apple path
  (`MetalBackend.mm:159-160,177-178`), matching FAISS-Metal's shared-storage trick.
